# مواجهة الوحوش — MTO

لعبة كروت استراتيجية **1 ضد 1** ضد خصم آلي: سطح مشترك من **272 كارت**، مطابقة عناصر وأرقام
على طريقة الأونو، نظام طاقة متصاعد، فخاخ تنطلق تلقائياً، هجمات مشتركة، ووحش أعظم يحسم المباراة فوراً.

مبنية على Next.js 16 (App Router) + Tailwind v4، جاهزة للنشر على **Vercel**، مع **Supabase** اختياري
لحفظ سجل المباريات.

---

## القواعد

### 1. السطح الأساسي — 272 كارت

| النوع | العدد | التفاصيل |
|---|---:|---|
| الوحوش | 120 | 6 عناصر × 5 فصائل × مرحلتين (أساسي/متطوّر) × نسختين |
| كروت الحركة | 36 | تخطي الدور (12)، اسحب كرتين (12)، انعكاس (4)، تغيير العنصر (4)، وحش بري + اسحب 4 (4) |
| الفخاخ | 54 | 27 تصميماً × نسختين |
| السحر | 54 | 27 تصميماً × نسختين |
| قطع الوحش الأعظم | 8 | قلب، ناب، درع، تاج × نسختين |

العناصر الستة: 🔥 نار · 💧 ماء · 🌿 عشب · ⚡ كهرباء · 🔮 نفسي · 🌑 ظلام.

خصائص الوحوش: **اندفاع** (يهاجم فور استدعائه) · **شحن** (+1 طاقة كل دور) · **حراسة** (‎-1 ضرر) ·
**اختراق** (الضرر الزائد يصيب اللاعب) · **امتصاص** (يشفي نصف الضرر) · **رابط** (يُدمج مع أي عنصر) ·
**استطلاع** (اسحب عند الاستدعاء) · **سُم** (1 ضرر للمهاجم).

### 2. دورة اللعب

- يبدأ كل لاعب بـ**5 كروت** و**30 نقطة حياة**؛ اللاعب الثاني يأخذ كارتاً تعويضياً، والبادئ لا يسحب في دوره الأول.
- في بداية كل دور: يرتفع سقف الطاقة +1 (من **2** حتى **10**)، وتُملأ الطاقة، ويُسحب كارت.
- خاصية «شحن» والفخاخ تمنح طاقة **فوق** السقف.

### 3. المطابقة والقتال

- كل كارت يجب أن يطابق **عنصر** أو **رقم** أعلى طابور التدفق (كالأونو). الكروت البرية تطابق كل شيء وتغيّر العنصر الفعّال.
- **الفخاخ وقطع الوحش** تُوضع دون شرط مطابقة — هذه هي مساحة المناورة. سقف الفخاخ المجهّزة **4**.
- **كروت السحب** تتكدّس: من يتلقّى العقوبة إما يردّ بكارت سحب مطابق فتتضاعف وتمرّ للخصم، وإما يقبل فيسحب ويفقد دوره.
- الهجوم المشترك: ادمج وحشين أو أكثر يشتركان في العنصر أو الرقم — أو أحدهما بخاصية «رابط» —
  بمكافأة +2 لكل وحش إضافي. مرة واحدة كل دور، وكارت «تضخيم» يضاعفه. سقف الساحة **6 وحوش**.
- الهجوم المباشر على اللاعب متاح فقط عندما تخلو ساحة الخصم من الوحوش.

### 4. الوحش الأعظم

اجمع القطع الأربع (قلب · ناب · درع · تاج) وادفع 6 طاقة → **فوز فوري**.
الفخ المضاد «تحطيم الأثر» يدمّر إحدى قطع الخصم ويعيدها إلى دورة السطح.

### 5. شروط الفوز

1. إسقاط حياة الخصم إلى الصفر.
2. استدعاء الوحش الأعظم.
3. إفراغ اليد عند نفاد كروت السطح.

`simulate` يتحقق من ثلاثة ثوابت: مجموع الكروت يبقى ثابتاً بلا تكرار، لا مباراة تتعثّر بلا نهاية،
وتوزيع الانتصارات معقول. اجعله جزءاً من أي تعديل على القواعد.

`check:tutorial` يمشي في خطوات الدرس وينفّذ الحركة المطلوبة في كل خطوة، ويفشل إذا طلب الدرس
شيئاً ترفضه القواعد (مثل لعب كارت لا تكفيه الطاقة) أو إذا كان شرط الإنجاز لا يتحقّق أبداً.
شغّله بعد أي تعديل على تكاليف الكروت أو على نصوص التعليم.

## الصوت

`lib/audio/sfx.ts` يولّد كل المؤثّرات بـWeb Audio — بلا ملفّات صوت: صفر بايت في الحزمة،
ولا تراخيص، ولا انتظار تحميل قبل أول صوت (مهمّ في تطبيق يعمل دون إنترنت).

الأصوات تُشتقّ من **سجل المباراة** (`lib/audio/logSfx.ts`)، فيصدر الصوت المناسب لكل حدث —
بما في ذلك ما يقع في دور الخصم — دون نثر نداءات صوت داخل المحرّك. وحين تقع أحداث كثيرة
في لحظة واحدة يُكتفى بأهمّ مؤثّرين حتى لا تتحوّل إلى ضجيج. زر 🔊 يكتم ويُحفَظ الإعداد.

## دليل اللاعب

`/guide` — سبعة أقسام تشرح ما لا تشرحه القواعد: ما هو طابور التدفق ولماذا يغيّره كل كارت
تلعبه، لماذا العناصر «مفاتيح» لا أفضلية ضرر، خطوات دمج البطاقات بالتفصيل، والفخاخ وكروت
السحب والوحش الأعظم. لكل قسم **سرّ** لا يُذكر في الشرح العادي. المحتوى في
`lib/i18n/guide.ts` باللغتين.

## اللغات

عربي وإنجليزي مع مبدّل في كل شاشة (`components/LanguageSwitch.tsx`). الاختيار يُحفظ في
`localStorage` ويُقرأ عبر `useSyncExternalStore` (`lib/i18n/store.ts`) — فلا يحدث تعارض ترطيب
بين الخادم والعميل، ولا `setState` داخل مؤثّر جانبي. تغيير اللغة يقلب `lang` و`dir` فوراً،
ويُترجم **حتى المباراة الجارية**.

كيف تحقّق ذلك: النصوص ثنائية اللغة تُخزَّن مع البيانات نفسها (`Localized = { ar, en }`) في
`cards.ts` و`difficulty.ts` و`tutorial.ts`، لا في قاموس منفصل يتخلّف عنها. وسجل المباراة
لا يخزّن نصّاً جاهزاً بل **مفتاحاً ومعاملات** (`lib/i18n/messages.ts`)، فيُترجَم وقت العرض.
أسماء اللاعبين المدمجة تُخزَّن كمفاتيح (`@you` / `@ai` / `@coach`) بينما تبقى الأسماء التي
يكتبها اللاعب كما هي.

**ملاحظة صياغة**: صيغ الملكية الإنجليزية (`{player}'s turn`) تنكسر حين يكون الاسم «You»،
فاستُبدلت بصيغ محايدة (`Turn: {player}`).

## صور الكروت

`components/game/CardArt.tsx` يولّد رسم كل كارت كـSVG من تعريف الكارت نفسه: الشكل يُشتقّ من
اسم الفصيلة (ستّة أنماط: وحش رباعي، أفعى، طائر، كرة، عملاق صخري، طيف)، والألوان من العنصر،
والمرحلة الثانية أضخم ومزيّنة بقرون وأجنحة وهالة. غير الوحوش لها رموز خاصّة لكل تأثير.

توليدها بدل ملفّات صور يعني: 134 تصميماً حادّاً في كل المقاسات، بلا بايت إضافي في الحزمة،
وتتبع ألوان العنصر تلقائياً — وإضافة كارت جديد تعطيه رسماً فوراً.

```bash
npm run cards:export -- --png
```

يصدّر كل تصميم صورةً كاملة (إطار + رسم + الاسم + النص + الإحصاءات) إلى `public/cards/`
بصيغتَي SVG وPNG بمقاس 420×600. الرسم يأتي من نفس المكوّن المستعمل في اللعبة فلا تتفرّع نسختان.

## أندرويد

### تطبيق قابل للتثبيت (PWA)
`manifest.webmanifest` + `public/sw.js`. عامل الخدمة يخزّن الأصول والصفحات، فتعمل المباريات
ضد الخصم الآلي والتعليم واللعب على جهاز واحد **دون إنترنت** بعد أول فتح. نداءات `/api` لا تُخزَّن.
من المتصفّح: «إضافة إلى الشاشة الرئيسية».

### حزمة APK
غلاف Capacitor أصلي (`capacitor.config.ts`) يحمّل النسخة المنشورة، فيبقى التطبيق محدَّثاً دون
إعادة تثبيت، وتعمل فيه كل المزايا بما فيها اللعب الجماعي.

```bash
npm run icons          # يولّد الأيقونات من الشعار
npx @capacitor/assets generate --android
npm run android:apk    # يرفع الإصدار تلقائياً، يبني APK، وينسخها إلى public/download/
```

### رقم الإصدار

المصدر الوحيد: `version` في `package.json`. يظهر في أسفل كل صفحة، بجانب رابط APK، وفي إعدادات تطبيق أندرويد.

| الأمر | متى تستخدمه |
|-------|-------------|
| `npm run version:bump` | رفع patch (`0.1.0` → `0.1.1`) |
| `npm run version:release` | رفع + مزامنة — قبل دفع تحديث الموقع |
| `npm run android:apk` | يرفع الإصدار تلقائياً (`SKIP_VERSION_BUMP=1` لتخطّي الرفع) |

الحزمة الحالية موقّعة بمفتاح debug — تُثبَّت وتُشارَك بعد تفعيل «مصادر غير معروفة».
لإصدار موقّع للنشر: أنشئ keystore، أضف `signingConfigs` في `android/app/build.gradle`،
ثم `npm run android:apk -- release`.

**ملاحظة بناء على ويندوز**: `scripts/build-apk.mjs` يجبر `java.io.tmpdir` على مسار قصير.
منتقي NIO ينشئ أنبوباً عبر مقبس AF_UNIX داخل مجلّد المؤقّت، وحدّ مسار المقبس ~108 بايت،
فإن كان مسار TEMP طويلاً فشل البناء برسالة مُضلّلة: «Unable to establish loopback connection».
ولهذا أيضاً عُطِّل `org.gradle.jvmargs` في `android/gradle.properties` ويُمرَّر من السكربت.

### روابط عميقة (App Links)

عند النقر على رابط `https://mto-game.vercel.app/...` من كروم أو الرسائل على أندرويد:

- **التطبيق مثبّت**: يُفتح غلاف Capacitor مباشرة على المسار (مثل `/vs/ABC`).
- **غير مثبّت**: يبقى الرابط في المتصفّح كالمعتاد.

الإعداد:

| الملف | الغرض |
|---|---|
| `android/app/src/main/AndroidManifest.xml` | `intent-filter` مع `autoVerify` لـ `mto-game.vercel.app` + مخطط `mto-game://` احتياطي |
| `public/.well-known/assetlinks.json` | بصمة SHA256 لمفتاح debug الحالي (`com.mto.monsterclash`) |
| `lib/deep-link.ts` | بناء `intent://` وفتح التطبيق من الويب |
| `components/DeepLinkHandler.tsx` | توجيه WebView عند فتح رابط والتطبيق يعمل |

**التحقق بعد النشر**: يجب أن يكون `assetlinks.json` متاحاً على
`https://mto-game.vercel.app/.well-known/assetlinks.json` حتى يتحقق أندرويد من App Links تلقائياً.

```bash
# محاكاة نقرة على رابط (بعد تثبيت APK)
adb shell am start -a android.intent.action.VIEW -d "https://mto-game.vercel.app/vs/test"

# حالة التحقق من الروابط
adb shell pm get-app-links com.mto.monsterclash
```

بصمة debug الحالية (SHA256): `08:BA:62:C4:...:6B:47`. عند إنشاء keystore إصدار، أضف بصمته إلى
`assetlinks.json` بجانب بصمة debug.

## اللعب الجماعي

### 🤝 على جهاز واحد — `/local`
لاعبان يتناوبان على نفس الشاشة. بين كل دور وآخر تظهر **ستارة تسليم** تخفي اللوحة حتى يضغط
اللاعب التالي، فلا يرى أحدهما يد الآخر. لا يحتاج إنترنت ولا أي إعداد.

### 🌐 أونلاين برمز غرفة — `/vs`
المضيف ينشئ غرفة فيحصل على رمز من 5 خانات، والضيف يدخله. القناة هي
Supabase Realtime Broadcast باسم `mto-room-<CODE>` — بلا جداول ولا تخزين.

**المضيف هو الحَكَم**: متصفّحه وحده يشغّل المحرّك. يستقبل حركات الضيف، يتحقّق أنها في دوره
(`current !== GUEST_SEAT` تُرفض)، يطبّقها، ثم يبثّ الحالة.

**ما يُبَثّ منقوص**: `redactFor(state, seat)` تستبدل يد الخصم وترتيب السطح وهوية الفخاخ المقلوبة
بكارت وهمي (`HIDDEN_CARD_ID`) مع الحفاظ على الأعداد. يتحقّق `npm run check:redact` من ذلك على
40 مباراة كاملة وفي كل حالة وسيطة من منظور الطرفين، ويفحص أيضاً ألا تتسرّب المعرّفات (`uid`).

**حدود معروفة**:
- المضيف يجب أن يبقى على الصفحة؛ إن أغلقها انتهت الغرفة (لا يوجد تخزين للاستئناف).
- المضيف يحمل الحالة الكاملة في متصفّحه، فهو قادر تقنياً على رؤية كروت الضيف بأدوات المطوّر.
  الضيف محميّ تماماً، والمضيف محكوم بالثقة — وهذا مقبول للّعب مع صديق.
  الحلّ الكامل يتطلّب تشغيل المحرّك على الخادم بمفتاح `SUPABASE_SERVICE_ROLE_KEY`.
- الغرفة تعتمد على رمز يُشارَك خارج اللعبة؛ من يعرف الرمز يمكنه الدخول.

## مستويات الصعوبة

`lib/game/difficulty.ts` — المستوى يضبط **الخصم وحده**، ولا يُمَسّ اللاعب:

| المستوى | حياة الخصم | سقف طاقته | نسبة خطئه | كروت التعطيل | الدمج | فوز اللاعب\* |
|---|---:|---:|---:|---:|:---:|---:|
| 🌱 سهل (الافتراضي) | 20 | 6 | 50% | 15% | لا | ~92% |
| ⚔️ متوسط | 26 | 8 | 22% | 55% | نعم | ~74% |
| 🔥 صعب | 30 | 10 | 0% | 100% | نعم | ~56% |

\* مقاسة بـ`npm run balance` حيث يلعب «اللاعب» بأفضل سياسة ممكنة؛ اللاعب البشري سيفوز أقل من ذلك.

«كروت التعطيل» هي تخطي الدور واسحب كرتين — أكثر ما يُحبط اللاعب الجديد، فيندر استعمالها في السهل.

## ترتيب اللعب

من يبدأ يُحدَّد **بالقرعة** في كل مباراة (`firstPlayer: 'random'` افتراضياً؛ التوزيع المُعدّ في
التعليم يبدأ دائماً باللاعب). تعويضاً لميزة البدء: من يلعب ثانياً يأخذ كارتاً وطاقة إضافية لمرة
واحدة، والبادئ لا يسحب في دوره الأول. النتيجة المقاسة: ميزة البدء **+1.0 نقطة مئوية** فقط.

## عدّاد الجولة

المهلة **ملك اللاعب لا ملك رقم الدور**، وتُمثَّل في الحالة بحقلَي `clockSeat` و`clockEpoch`
(`lib/game/types.ts`). الحقبة تزيد في `beginTurn` **فقط** حين يبدأ لاعب مختلف دوراً يتصرّف فيه
فعلاً، فتُصفَّر المهلة عندئذ وحده:

| ما لعبته | رقم الدور | العدّاد |
|---|---|---|
| «تخطي» أو «انعكاس» في 1×1 | +2 (يعود إليك) | **يستمر** — لا مهلة مجانية |
| «تغيير العنصر» | لا يتغيّر | يستمر |
| «اسحب كرتين» أو «اسحب 4» | +1 إلى الخصم | يبدأ الخصم بمهلة كاملة |
| إنهاء الدور | +1 | مهلة كاملة للتالي |

جعل العدّاد جزءاً من حالة المحرّك بدل استنتاجه في الواجهة يعني أنه **حتمي** ويتزامن بين المضيف
والضيف مجاناً بدل حسابه مرّتين. الدور المُتخطَّى لا يبتلع حقبة لأن `armClock` لا يُنادى في فرع
`skipNext` — فاللاعب هناك لا يتصرّف أصلاً. يحرس ذلك `npm run check:clock`.

## التعليم

`/tutorial` درس تفاعلي من 12 خطوة على توزيع ثابت (`lib/game/tutorial.ts`): يشرح قراءة الكارت،
قاعدة المطابقة، الطاقة، الاستدعاء وخاصية «اندفاع»، الهجوم، الفخاخ، قطع الوحش الأعظم، والهجوم
المشترك. الخطوات الفعلية تتقدّم تلقائياً عند تنفيذ الحركة، ولكل خطوة زر «تخطَّ» حتى لا يعلق اللاعب.
وداخل أي مباراة، زر «؟ كيف ألعب» يفتح مرجعاً سريعاً.

## وضع البقاء — أكشن 2D (`/arcade`)

لعبة حركة 2D منفصلة عن نظام الكروت لكن بنفس ثيم MTO: عناصره الستّة، وأشكال وحوشه
الستّة (وحش/أفعى/طائر/كرة/عملاق/طيف)، والوحش الأعظم، وقطعه الأربع. تُرسم كلّها على **Canvas**
للأداء الحيّ. الشاشة نفسها هي الساحة، والأعداء يتوافدون من الحواف.

- **التحكم**: اسحب في أي مكان لتحريك بطلك (جويستيك طافٍ)، والإطلاق تلقائي على أقرب عدو —
  لعب بإصبع واحد. لوحة المفاتيح (WASD/الأسهم) مدعومة للتجربة على سطح المكتب.
- **الارتقاء**: اجمع كرات الخبرة من الأعداء لترتقي، فتختار قوّة عنصرية من ثلاث (12 ترقية:
  ترقيتان لكل عنصر — لهب/كرة نار، حيوية/تجدّد، امتصاص/هالة سُم، إطلاق سريع/خفّة،
  انقسام/جذب، اختراق/مدارات ظلّ). اختيار عنصرك في البداية يمنحك قوّته التوقيعية مجاناً.
- **الزعيم**: يظهر **الوحش الأعظم** دورياً بوابل قذائف شعاعية؛ إسقاطه يُسقط قطعة. جمع القطع
  الأربع يطلق «صعوداً» يمسح الساحة ويمنحك تعزيزاً دائماً، فتتصاعد الصعوبة بلا نهاية.
- **العمق والحيوية**: خلفية **منظورية (parallax)** بعدّة طبقات (سُدُم/نجوم/شبكة) تتحرّك بسرعات
  مختلفة مع البطل، و**إضاءة ديناميكية** (هالة ضوء حول البطل، ومضات عند الانفجارات، وتظليل حوافّ).
- **الصوت**: يعيد استخدام مولّد Web Audio نفسه (`lib/audio/sfx.ts`) — بلا ملفّات.
- بلا حالة على الخادم: أفضل زمن يُحفظ في `localStorage`. يعمل دون إنترنت ضمن الـPWA وغلاف Capacitor.

المحرّك (`lib/arcade/engine.ts`) قائم بذاته على Canvas؛ الـHUD يُرسم داخل اللوحة، والقوائم
(بداية/ترقية/نهاية) طبقة React فوقها (`components/arcade/ArcadeCanvas.tsx`).

## وضع البقاء — أكشن 3D (`/arcade3d`)

النظير **ثلاثي الأبعاد** لوضع البقاء، بـ**Three.js** (WebGL). نفس اللعب والثيم والترقيات
والوحش الأعظم، لكن في ساحة مجسّمة: كاميرا تتبع البطل من أعلى-خلف، والأعداء يتوافدون من حلقة حوله.

- **يعيد استخدام منطق البقاء نفسه**: يستورد الإحصاءات والترقيات الاثنتَي عشرة والثيم والنصوص
  من `lib/arcade`، ويحافظ على **نفس المقياس العددي** للمحرّك 2D فتعمل كل القيم دون تعديل.
- **المُجسّمات** (`lib/arcade3d/meshes.ts`): الأشكال الستّة تُبنى من أشكال أوّلية (كرة/صندوق/مخروط/
  حلقة) بألوان العناصر وخامات وهّاجة؛ الهندسات والخامات مشتركة، والقالب يُستنسخ رخيصاً لكل عدو.
  الجسيمات على GPU عبر `THREE.Points`.
- **واقعية**: **ظلال ديناميكية** (shadow maps ناعمة PCF بدقّة 2048 وإطار يتبع البطل بزاوية منخفضة)،
  **إضاءة قائمة على البيئة (IBL)** مولّدة بـPMREM مع **tone mapping سينمائي (ACES)**، و**خامات PBR**
  (بطل بلّوري بطلاء لامع `MeshPhysicalMaterial`، انعكاسات بيئية، وأرضية بخريطتَي خشونة ونتوءات)،
  و**خرائط نتوءات (normal maps)** إجرائية على الوحوش، وضوء نقطي يتبع البطل بلون عنصره.
- **توهّج (Bloom)**: post-processing عبر `EffectComposer` + `UnrealBloomPass` + `OutputPass`
  (من `three/addons`) يُبرز العناصر المضيئة؛ الرسم يمرّ بالمُركّب بدل `renderer.render` المباشر.
- **جودة تكيّفية (Adaptive Quality)**: يقيس المحرّك FPS ويتنقّل تلقائياً بين ثلاثة مستويات
  (عالية/متوسطة/منخفضة) مع hysteresis — يخفض دقّة الظلّ ويعطّل Bloom ويقلّل نسبة البكسل عند الحاجة،
  فيبقى اللعب انسيابياً على الأجهزة الأضعف دون التضحية بالجودة على القويّة. المستوى يظهر في الـHUD حين ينزل عن «العالية».
- **التحكم**: جويستيك طافٍ باللمس (يُسقَط على المستوى الأفقي) + لوحة مفاتيح على سطح المكتب.
- **HUD**: طبقة DOM تُحدَّث **إمبراطيفياً عبر المراجع** (بلا إعادة رسم React) من نداء `onHud`
  في كل إطار — فتبقى حلقة اللعب سلسة.
- أفضل زمن مستقلّ في `localStorage` (`mto-arcade3d-best`). يتحقّق `Three.js` من دعم WebGL،
  ويتراجع بأمان إن غاب.

يضيف هذا الوضع تبعية **`three`** إلى `package.json`. المحرّك في `lib/arcade3d/engine3d.ts`
والواجهة في `components/arcade3d/Game3D.tsx`.

## الحسابات والأصدقاء

**الحساب مطلوب للّعب الجماعي وحده.** اللعب ضد الخصم الآلي، والتعليم، واللعب على جهاز واحد،
ووضع البقاء تعمل كلّها بلا حساب ودون إنترنت كما كانت. البوّابة (`components/auth/AuthGate.tsx`)
مركَّبة في `OnlineGame` و`RoomLobby` وصفحات `/vs` — **لا في `GameBoard`**، لأن اللوح نفسه يخدم
`/play` و`/local` و`/tutorial`.

### اسم مستخدم وكلمة مرور بلا بريد

Supabase Auth يتطلّب بريداً، فيُشتقّ بريد صوريّ معمّى من اسم المستخدم
(`lib/auth/username.ts`): `u<sha256("mto:v1:"+norm)…>@users.mto-game.vercel.app`.

- الدخول لا يحتاج بحثاً مسبقاً في جدول، فلا ينشأ مسار يُحصي المستخدمين.
- التطبيع يوحّد `أ إ آ`→`ا` و`ى`→`ي` و`ة`→`ه` ويزيل التشكيل، فمن كتب «أحمد» يجد «احمد».
- **التطبيع نهائي**: تغييره يقطع دخول كل الحسابات القائمة، ويحرسه `npm run check:auth` ببريد مثبَّت.
- **لا استعادة لكلمة المرور** — لا بريد حقيقي يُرسَل إليه شيء. النموذج يقول ذلك صراحةً.

### المستوى والإحصاءات

المستوى **عمود مولَّد مخزَّن** في `profiles`: دالة في عدد الانتصارات، والانتصارات لا تُكتب إلا عبر
`record_match` — فالانحراف مستحيل بنيوياً. الانتقال من المستوى N إلى N+1 يكلّف `3N` انتصاراً.
نسخة TS في `lib/player/level.ts` لشريط التقدّم وحده، يحرس تطابقها `npm run check:level`.

«أكثر الكروت لعباً» و«أكثر العناصر» تُشتقّان من سجل المباراة **خارج المحرّك** (`lib/game/stats.ts`)
فيبقى مُختزِلاً خالصاً. التجميع تزايديّ على `logSeq` لا على طول السجل، لأن السجل حلقة تُقصّ عند
200 سطر فالقراءة الدفعية تفقد أوائل المباريات الطويلة. **الفخاخ عدّاد منفصل** لا تدخل «أكثر
الكروت»: هويّة الفخّ المقلوب لا تُسجَّل عمداً حتى لا يقرأها الخصم من السجل المبثوث.

### الدعوة: لوبي جديد أو لوبي مفتوح

الغرف بلا تخزين على الخادم كما كانت؛ صفّ `game_invites` هو نقطة الالتقاء العابرة (3 دقائق).
`LobbyFriendsPanel` يشتقّ وضعه من خصائصه:

| السياق | الزرّ | السلوك |
|---|---|---|
| بلا رمز غرفة (`/vs` و`/friends`) | «ادعُ إلى لوبي جديد» | يولّد رمزاً، يُدرج الدعوة، ثم يدخل مضيفاً |
| مع رمز ومقعد شاغر | «ادعُ إلى هذا اللوبي» | يُدرج الدعوة بالرمز الحالي **بلا تنقّل** |
| بلا مقعد شاغر أو بعد بدء المباراة | معطّل مع سبب | — |

وهذا ما يجعل **1×1×1 قابلاً للتكوين من الأصدقاء**: افتح غرفة ثلاثية، ادعُ الأول، وحين ينضمّ
ادعُ الثاني إلى الغرفة نفسها. التسابق على آخر مقعد لا يحتاج حجزاً: `claimSeat` يردّ الثاني
بـ`roomFull` وتعرضها `OnlineGame` عبر فرع الخطأ القائم.

**`clientId` يبقى هو مالك المقعد** (`sessionStorage`، لكل تبويب). `userId` يُحمَل إلى جانبه
للعرض والنسبة فقط: معرّف ثابت لكل حساب كان سيجعل تبويباً ثانياً يسرق مقعد الأول.

## Supabase (اختياري)

اللعبة تعمل بالكامل بدونه؛ عند غيابه تظهر رسالة واضحة في صفحة السجل ولا تُحفظ النتائج،
ويشرح `/vs` أن اللعب الجماعي غير مهيّأ.

1. شغّل الترحيلين بالترتيب على مشروعك:
   - `supabase/migrations/0001_init.sql`
   - `supabase/migrations/0002_accounts.sql` — **بـ`supabase db push` أو من محرّر SQL في اللوحة**،
     لأن مُشغّل `auth.users` يحتاج صلاحية مرتفعة لا يملكها مفتاح REST.
2. أضف المتغيّرات (انظر `.env.example`).
3. **أطفئ التسجيل العام** من إعدادات Auth في اللوحة: مسار `/api/auth/register` ينادي
   `admin.createUser` فيتخطّى ذلك المفتاح ويبقى تسجيلنا يعمل، بينما لا يستطيع أحد إنشاء حساب
   بلا ملفّ شخصي عبر `POST /auth/v1/signup` بالمفتاح المجهول.

الجدول `matches` يبقى كما كان: سجلّ عامّ مجهول الهوية، قراءة عامة وإضافة فقط.
جداول الحسابات (`profiles`, `friendships`, `direct_messages`, `game_invites`, `match_records`,
`profile_card_stats`) **ممنوعة على المفتاح المجهول تماماً**، والعدّادات لا تُكتب إلا عبر
`record_match` — سياسة `update` وحدها كانت ستتيح `set wins = 9999`، والمانع الفعلي هو
`grant update (display_name)` على مستوى العمود.

**إصلاح مضمَّن**: `0002` يضيف عمود `difficulty` الناقص إلى `matches`. المسار
`app/api/matches/route.ts` كان يُدرجه ويقرأه بينما `0001_init.sql` لا ينشئه، فكان كل حفظ
نتيجة يفشل بـ500 على قاعدة نظيفة.

## النشر

`scripts/deploy.ps1` يجمع المراحل الثلاث في مكان واحد: **GitHub ← Supabase ← Vercel**.
الترتيب مقصود — الهجرة قبل النشر، وإلا وصل كودٌ يقرأ جداول لم تُنشأ بعد.

```powershell
# اعرض ما سيحدث دون لمس شيء — ابدأ من هنا دائماً
.\scripts\deploy.ps1 -DryRun

# مرحلة واحدة
.\scripts\deploy.ps1 -Stage github -Message "إضافة الحسابات"
.\scripts\deploy.ps1 -Stage supabase
.\scripts\deploy.ps1 -Stage vercel

# الثلاث مراحل، ونشر إنتاجي
.\scripts\deploy.ps1 -Prod
```

| الخيار | المعنى |
|---|---|
| `-Stage` | `all` (الافتراضي) · `github` · `supabase` · `vercel` |
| `-Prod` | نشر إنتاجي؛ بدونه معاينة |
| `-Remote` | ريموت git، الافتراضي `mphpmaster` |
| `-Message` | رسالة الالتزام (تُطلب تفاعلياً إن غابت) |
| `-DryRun` | اطبع كل خطوة دون تنفيذ |
| `-SkipChecks` | تخطّي فحوص المشروع — لا تستعمله إلا وأنت تعرف لماذا |
| `-Yes` | لا تسأل (لـCI فقط، ويلزمه `-Message`) |

> **ملاحظة**: مخرجات السكربت بالإنجليزية عمداً — رسائل تشغيل تُقرأ بجانب مخرجات `git`
> و`vercel` و`supabase` — بينما تعليقات الكود بالعربية كبقيّة المستودع.

**مبادئ مقصودة**:
- **لا سرّ في السكربت ولا في المستودع**: المفاتيح تُقرأ من متغيّرات البيئة أو تُطلب كنصّ مخفيّ
  (`-AsSecureString`)، ولا تُطبع ولا تُكتب في ملف. و`.env*` مُستثنى من git عدا `.env.example`.
- **كل ما يخرج عن جهازك يُعرَض ثم يُستأذَن**: الالتزام، والدفع، والهجرة، والنشر.
- **الفحوص تسبق النشر**: `typecheck` و`check:auth` و`check:level` و`check:social` و`check:clock`
  و`check:effects` و`check:messages` و`check:redact` و`simulate` — وأي فشل يوقف النشر.
- **Supabase عبر `npx`** فلا يُفرض على أحد تثبيت CLI عام ليدفع كوداً. اربط المشروع مرّة واحدة:
  `npx supabase link --project-ref <ref>`.

### حين يرفض `db push`

هجرات هذا المستودع مرقّمة `0001`/`0002` لا بطوابع زمنية، بينما يتتبّع CLI النسخَ في جدول
`supabase_migrations.schema_migrations` على الخادم. فإن حمل الخادمُ نسخاً لا توجد محلياً — لأن
المشروع أُعِدّ من اللوحة أو من مستودع آخر — رفض `db push` العملَ كلَّها برسالة
«Remote migration versions not found in local migrations directory».

السكربت **لا يعيد كتابة تاريخ الهجرات على قاعدة حيّة تلقائياً**؛ يعرض الخيارات ويقف:

| الخيار | متى |
|---|---|
| **أ) طبّق SQL يدوياً** من محرّر SQL في اللوحة | الأبسط والموصى به |
| ب) `npx supabase db pull` ثم `db push` | حين تريد مزامنة التاريخ فعلاً |
| ج) `supabase migration repair --status applied <versions>` | حين تتيقّن أنها مُطبَّقة |

**احذر اقتراح CLI نفسه**: يقترح `--status reverted`، أي إعلان أن تلك الهجرات قد تراجعت — فإن
كانت مُطبَّقة فعلاً تركتَ التاريخ يكذب على قاعدتك.

`0002_accounts.sql` مكتوب ليُعاد تشغيله بأمان (`if not exists` و`create or replace` و
`drop policy if exists`)، ودالة `level_from_wins` محروسة بـ`do $$ … if not exists` لأن
`create or replace` عليها يفشل بعد إنشاء عمود `profiles.level` المولَّد الذي يعتمد عليها.

الإعدادات في `vercel.ts`. وإن فضّلت العمل يدوياً فالأوامر المكافئة:

```bash
git push mphpmaster <branch>
npx supabase db push
vercel deploy --prod
```
